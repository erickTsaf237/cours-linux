    Le bureau GNOME en 5 minutes

    Ubuntu utilise l'environnement de bureau GNOME (version 46 sur Ubuntu 24.04), légèrement personnalisé par Canonical : dock à gauche, thème orange et violet. Voici ses zones principales.

    Les espaces de travail

    GNOME crée des bureaux virtuels à la demande. Mets ton navigateur sur le premier, tes terminaux sur le second, et passe de l'un à l'autre avec Super + Pg↓. C'est l'une des fonctions que les habitués de Linux regrettent le plus ailleurs.

    Terminal, console, shell : qui fait quoi ?

    On utilise souvent ces mots comme synonymes, mais ils désignent trois choses différentes. Quand tu tapes une commande, elle traverse cette chaîne :

    ⌨️
    Toitu tapes ls
    →
    🪟
    Le terminalla fenêtre : affiche et transmet le texte
    →
    🐚
    Le shellBash : comprend et lance la commande
    →
    🐧
    Le noyauexécute le programme
    Terminal
    Le programme-fenêtre qui affiche du texte et lit le clavier. Sur Ubuntu : Terminal (GNOME Terminal). On dit aussi émulateur de terminal : il imite les terminaux physiques des années 70.
    Console (TTY)
    Un terminal en plein écran, sans interface graphique. Essaie Ctrl + Alt + F3, puis reviens avec Ctrl + Alt + F2 (ou F1). Précieux quand l'interface graphique plante.
    Shell
    L'interpréteur de commandes : il lit ce que tu tapes, le comprend et lance les programmes. Celui d'Ubuntu s'appelle Bash.
    Invite (prompt)
    Le texte que le shell affiche quand il attend une commande : user@ubuntu:~$.
    Pourquoi « terminal » ?

    Dans les années 70, un ordinateur occupait une pièce entière. Les utilisateurs s'y connectaient depuis des terminaux : un écran et un clavier, sans aucune puissance de calcul, reliés à l'ordinateur par un câble. Avant eux, on utilisait des téléscripteurs (teletypewriters) qui imprimaient sur du papier. C'est de là que vient l'abréviation TTY… qu'on retrouve encore partout dans Linux, 50 ans plus tard.

    Tes premières commandes

    Ouvre un terminal (Ctrl + Alt + T) et tape ces commandes une à une. Rien de dangereux : elles ne font qu'afficher des informations.

    user@ubuntu:~$ whoami                 # qui suis-je ?
user
user@ubuntu:~$ hostname               # sur quelle machine ?
ubuntu
user@ubuntu:~$ pwd                    # où suis-je ? (print working directory)
/home/user
user@ubuntu:~$ date                   # quelle heure est-il ?
mer. 22 oct. 2026 14:32:07 CEST
user@ubuntu:~$ uptime -p              # depuis quand la machine tourne-t-elle ?
up 2 hours, 14 minutes
user@ubuntu:~$ echo "Bonjour Linux"   # afficher un texte
Bonjour Linux
user@ubuntu:~$ ls                     # que contient ce dossier ?
Bureau  Documents  Images  Modèles  Musique  Public  Téléchargements  Vidéos  snap
user@ubuntu:~$ history                # les commandes déjà tapées
user@ubuntu:~$ clear                  # effacer l'écran
user@ubuntu:~$ exit                   # fermer le shell (et le terminal)
    Le silence est d'or

    Une commande qui réussit n'affiche souvent rien. C'est voulu : sous Linux, « pas de nouvelles, bonnes nouvelles ». Seules les erreurs font du bruit. Tu t'en rendras compte avec mkdir ou cp au prochain module.

    L'anatomie d'une commande

    Toutes les commandes suivent la même grammaire. Une fois qu'on l'a comprise, on peut lire n'importe quelle commande :

    lscommandequoi faire
    -l -aoptionscomment le faire
    /etcargumentsur quoi le faire
    • La commande vient toujours en premier : c'est le nom du programme à lancer.
    • Les options modifient son comportement. Elles commencent par un tiret.
    • Les arguments indiquent sur quoi agir : un fichier, un dossier, un texte…
    • Les éléments sont séparés par des espaces. Un espace en trop ou en moins change tout.

    Options courtes et options longues

    FormeExempleParticularité
    Courte : un tiret, une lettrels -l -a -hSe combinent : ls -lah = ls -l -a -h
    Longue : deux tirets, un motls --all --human-readablePlus lisibles, idéales dans les scripts
    Avec valeurls --sort=size, head -n 5L'option attend une valeur
    user@ubuntu:~$ ls -lah /etc/hostname
-rw-r--r-- 1 root root 7 oct.  22 09:12 /etc/hostname
# -l : format long   -a : fichiers cachés inclus   -h : tailles lisibles (K, M, G)
    Linux respecte la casse

    Majuscules et minuscules sont différentes : ls fonctionne, LS ou Ls non. Il en va de même pour les fichiers : Photo.jpg et photo.jpg sont deux fichiers distincts, qui peuvent cohabiter dans le même dossier.

    Les espaces et les guillemets

    Puisque l'espace sépare les arguments, un nom qui contient un espace doit être protégé par des guillemets :

    user@ubuntu:~$ ls Mes Documents        # 2 arguments : « Mes » et « Documents »
ls: impossible d'accéder à 'Mes': Aucun fichier ou dossier de ce nom
user@ubuntu:~$ ls "Mes Documents"      # 1 seul argument

    C'est pourquoi les habitués de Linux évitent les espaces dans les noms de fichiers : mes-documents ou mes_documents.

    Toutes les commandes ne sont pas des programmes

    La commande type révèle la vraie nature d'une commande :

    user@ubuntu:~$ type ls cd ll
ls est un alias vers « ls --color=auto »
cd est une primitive du shell
ll est un alias vers « ls -alF »
user@ubuntu:~$ which date
/usr/bin/date
    Programme
    Un fichier exécutable sur le disque, comme /usr/bin/date. which indique où il se trouve.
    Primitive (builtin)
    Une commande intégrée au shell lui-même, comme cd, echo ou exit.
    Alias
    Un raccourci défini par l'utilisateur ou la distribution. Ubuntu fournit ll = ls -alF. Tu créeras les tiens au module 09.

    ↑ ↓

    Ctrl + A / Ctrl + EAller au début / à la fin de la ligne

user@ubuntu:~$ sudo !!
sudo apt update                 # Bash affiche la commande reconstituée, puis l'exécute
    Le réflexe Tab

    Prends l'habitude d'appuyer sur Tab après deux ou trois lettres, tout le temps. Tu tapes moins, et surtout tu ne fais plus de fautes de frappe : si la complétion ne propose rien, c'est que le nom n'existe pas.

    Trouver de l'aide sans quitter le terminal

    Personne ne connaît toutes les options de toutes les commandes. Ce qui fait la différence, c'est de savoir où chercher. Quatre outils, du plus rapide au plus complet :

    1. --help : l'aide-mémoire

    user@ubuntu:~$ ls --help
Utilisation : ls [OPTION]... [FICHIER]...
Afficher des renseignements sur les FICHIERs (du répertoire actuel par défaut).
  -a, --all                  ne pas ignorer les entrées débutant par .
  -h, --human-readable       avec -l et -s, afficher les tailles comme 1K 234M 2G etc.
...

    Dans cette notation, [...] signifie « facultatif » et ... « peut être répété ».

    2. man : le manuel officiel

    Chaque commande a sa page de manuel, complète et précise. man ls l'ouvre dans un lecteur où l'on navigue au clavier :

    ToucheAction dans man
    Espace / BPage suivante / précédente
    ↑ ↓Ligne par ligne
    / + mot + EntréeRechercher un mot, puis N pour l'occurrence suivante
    G / Maj + GDébut / fin de la page
    QQuitter (la touche que tout le monde cherche la première fois)

    Le manuel est découpé en sections numérotées. Le même mot peut exister dans plusieurs sections :

    SectionContenuExemple
    1Commandes utilisateurman 1 passwd : la commande passwd
    5Formats de fichiers de configurationman 5 passwd : le fichier /etc/passwd
    8Commandes d'administration (souvent avec sudo)man 8 useradd
    2, 3Appels système, bibliothèques (pour développeurs)man 2 open
    user@ubuntu:~$ man -k partition       # chercher une commande par mot-clé (= apropos)
fdisk (8)            - manipulateur de table de partitions pour Linux
parted (8)           - a partition manipulation program
...
user@ubuntu:~$ whatis ls               # la description en une ligne
ls (1)               - Afficher le contenu de répertoires

    3. help : pour les primitives du shell

    Les commandes intégrées à Bash, comme cd, n'ont pas de page man à elles. On utilise help : help cd.

    4. tldr : des exemples, tout de suite

    TL;DR signifie « trop long, pas lu ». Cet outil communautaire affiche les exemples les plus utiles d'une commande, sans le roman :

    user@ubuntu:~$ sudo apt install tldr
user@ubuntu:~$ tldr --update      # télécharge les fiches (à faire une fois)
user@ubuntu:~$ tldr tar
  Archiving utility.
  - Create an archive and write it to a file:
    tar cf path/to/target.tar path/to/file1 path/to/file2 ...
  - Extract a (compressed) archive file into the current directory verbosely:
    tar xvf path/to/source.tar[.gz|.bz2|.xz]
...
    La bonne stratégie

    tldr pour l'exemple rapide → --help pour la liste des options → man pour comprendre en profondeur. Internet vient en dernier, et quand tu y trouves une commande, vérifie-la avec man avant de la lancer, surtout avec sudo.

    Lire un message d'erreur

    Un message d'erreur n'est pas un échec : c'est une information précise. La plupart suivent le format commande: objet: problème. Les plus fréquents :

    MessageSignificationQue faire
    command not foundLa commande n'existe pas ou n'est pas installéeVérifier l'orthographe (Tab) ; Ubuntu suggère souvent le paquet à installer
    No such file or directory
    (Aucun fichier ou dossier de ce nom)    		Le chemin donné n'existe pasVérifier le chemin, la casse, les espaces
    Permission denied
    (Permission non accordée)    		Tu n'as pas les droits nécessairesEst-ce normal ? Si oui et si tu sais ce que tu fais : sudo
    invalid optionOption inconnue de cette commandecommande --help
    missing operandIl manque un argumentRelire l'utilisation dans --help
    Le code de retour

    Chaque commande renvoie un nombre en se terminant : 0 si tout va bien, autre chose en cas d'erreur. echo $? affiche celui de la dernière commande. Il deviendra indispensable dans les scripts (module 16).

    🧠 Quiz : as-tu tout retenu ?

    1. Quel programme lit et interprète les commandes que tu tapes ?
    Le terminal affiche et transmet le texte ; c'est le shell qui comprend et lance la commande.
    2. Dans ls -l /etc, que représente /etc ?
    /etc est l'argument : ce sur quoi la commande agit. -l est l'option.
    3. ls -lah est équivalent à…
    Les options courtes se combinent derrière un seul tiret.
    4. Comment quitter une page de manuel man ?
    Q comme quit. Valable aussi dans less, que tu verras au module 03.
    5. Une commande tourne indéfiniment. Comment l'arrêter ?
    Ctrl + C interrompt la commande. (Ctrl + Z la met seulement en pause : on verra ça au module 07.)
    6. man passwd et man 5 passwd affichent…
    Sans numéro, man prend la première section trouvée (1, les commandes). La section 5 décrit les fichiers.
    7. Tu tapes Ls et obtiens « command not found ». Pourquoi ?
    La commande s'appelle ls, en minuscules. Ls est un autre nom, qui n'existe pas.
    8. Que fait sudo !! ?
    !! est remplacé par la commande précédente. Pratique quand on a oublié sudo.

    💬 Questions fréquentes

    Les questions qui reviennent le plus souvent sur ce module, avec leurs réponses.

    Je suis bloqué dans un écran dont je ne sais pas sortir !

    Selon ce que tu vois, essaie dans cet ordre :

    • Q : pour quitter man, less, top…
    • Ctrl + C : pour interrompre une commande qui tourne ou attend.
    • Ctrl + D : pour terminer une saisie (une commande qui attend du texte).
    • Échap puis :q! et Entrée : si tu es tombé dans l'éditeur Vim (on l'apprivoisera au module 03).
    La commande man répond « No manual entry for … »

    Soit la commande est une primitive du shell (utilise help commande), soit le paquet ne fournit pas de manuel. Essaie alors commande --help ou tldr commande. type commande te dira de quel cas il s'agit.

    Pourquoi certaines commandes affichent du français et d'autres de l'anglais ?

    Les messages sont traduits par chaque projet. Si la traduction française n'existe pas, la commande s'affiche en anglais. Astuce : préfixer une commande par LANG=C force l'anglais (LANG=C ls --help), pratique pour rechercher un message d'erreur sur Internet.
