    Les trois flux standard

    Tout programme démarre avec trois canaux ouverts, numérotés :

    N°NomRôlePar défaut
    0stdinEntrée standard : ce que le programme litLe clavier
    1stdoutSortie standard : les résultatsL'écran
    2stderrSortie d'erreur : les messages d'erreurL'écran

    Les redirections

    > écrase sans prévenir

    sort notes.txt > notes.txt vide le fichier : le shell le tronque avant même que sort ne le lise. On écrit toujours dans un autre fichier, puis on renomme. Pour se protéger, set -o noclobber fait refuser à Bash l'écrasement avec >.

    L'ordre compte : 2>&1

    2>&1 signifie « envoie stderr là où va stdout en ce moment ». Dans cmd > f 2>&1, stdout va déjà dans f : tout y va. Dans cmd 2>&1 > f, stderr a été branché sur l'écran avant que stdout ne soit redirigé : les erreurs restent à l'écran.

    Écrire plusieurs lignes : le « here-document »

    user@ubuntu:~$ cat > courses.txt << 'FIN'
> pommes
> pain
> café
> FIN
user@ubuntu:~$ cat courses.txt
pommes
pain
café

    Tout ce qui est tapé jusqu'au mot FIN (seul sur sa ligne) est envoyé sur stdin. Très utilisé dans les scripts pour créer des fichiers de configuration.

    Le pipe : l'art de combiner

    Le pipe | (AltGr + 6 sur un clavier AZERTY) branche le stdout d'une commande sur le stdin de la suivante. Les données coulent d'un programme à l'autre, sans fichier intermédiaire, et tous les programmes tournent en même temps.

    📜
    cat acces.logtoutes les lignes
    |
    ✂️
    cut -d' ' -f1garde l'adresse IP
    |
    🔤
    sortregroupe les identiques
    |
    🔢
    uniq -ccompte
    |
    🏆
    sort -nr | headle top
    Une idée de 1973

    Le pipe a été proposé par Doug McIlroy aux Bell Labs et ajouté à Unix par Ken Thompson en 1973, en une nuit selon la légende. McIlroy a résumé la philosophie qui en découle : « Écrivez des programmes qui font une seule chose et la font bien. Écrivez des programmes qui travaillent ensemble. Écrivez des programmes qui manipulent des flux de texte. »

    Construire un pipeline pas à pas

    Ne tape jamais un long pipeline d'un coup. Ajoute une commande à la fois, regarde le résultat, puis rappelle la ligne avec ↑ et ajoute le maillon suivant. C'est comme ça que les pros procèdent.

    La boîte à filtres

    grep : garder les lignes qui correspondent

    OptionEffetExemple
    Lignes contenant le motifgrep 404 acces.log
    -iIgnorer majuscules/minusculesgrep -i error /var/log/syslog
    -vInverser : lignes qui ne correspondent pasgrep -v '^#' fichier.conf
    -cCompter les lignesgrep -c 403 acces.log
    -nAfficher les numéros de lignegrep -n root /etc/passwd
    -rChercher dans tous les fichiers d'un dossiergrep -r "Port" /etc/ssh/
    -wMot entier seulementgrep -w log fichier
    -EExpressions régulières étenduesgrep -E '40[134]' acces.log

    Les expressions régulières (^ début de ligne, $ fin, . n'importe quel caractère…) seront approfondies au module 06.

    Aperçu de sed et awk

    Deux outils plus puissants, presque des langages à eux seuls. L'essentiel suffit pour 90 % des usages.

    sed : rechercher et remplacer dans un flux

    user@ubuntu:~/labo$ sed 's/GET/LECTURE/' acces.log | head -2       # s/ancien/nouveau/ : 1re occurrence par ligne
192.168.1.10 - - [23/Oct/2026:10:01:12] "LECTURE /index.html" 200 5120
192.168.1.22 - - [23/Oct/2026:10:01:15] "LECTURE /contact.html" 200 2048
user@ubuntu:~/labo$ sed 's/a/A/g' courses.txt                 # g : toutes les occurrences
user@ubuntu:~/labo$ sed -n '3,5p' acces.log                   # afficher les lignes 3 à 5
user@ubuntu:~/labo$ sed '/403/d' acces.log                     # supprimer les lignes contenant 403
user@ubuntu:~/labo$ sed -i.bak 's/pain/baguette/' courses.txt   # -i : modifie le fichier (copie .bak)

    awk : travailler par colonnes

    awk découpe chaque ligne en champs $1, $2… (séparés par des espaces, ou par ce que précise -F) et permet des conditions et des calculs.

    Dans notre journal, la méthode "GET forme un champ à elle seule : l'IP est $1, la page $6, le code HTTP $7 et la taille $8.

    user@ubuntu:~/labo$ awk '{print $1, $7}' acces.log | head -2      # IP et code HTTP
192.168.1.10 200
192.168.1.22 200
user@ubuntu:~/labo$ awk '$7 >= 400' acces.log | wc -l          # nombre de requêtes en erreur
5
user@ubuntu:~/labo$ awk '{total += $8} END {print total " octets"}' acces.log
50688 octets
user@ubuntu:~$ awk -F: '$3 >= 1000 {print $1}' /etc/passwd       # les comptes humains
user
nobody

    Glossaire du module

    stdin / stdout / stderr
    Entrée standard (0), sortie standard (1), sortie d'erreur (2).
    Redirection
    Changer la destination ou la source d'un flux : >, >>, 2>, <.
    /dev/null
    Fichier spécial qui avale tout ce qu'on lui envoie.
    Here-document
    Bloc de texte envoyé sur stdin avec << MOT.
    Pipe
    | : relie le stdout d'une commande au stdin de la suivante.
    Pipeline
    Chaîne de commandes reliées par des pipes.
    Filtre
    Programme qui lit stdin, transforme, et écrit sur stdout.
    grep
    Garde les lignes qui correspondent à un motif.
    sed
    Éditeur de flux : remplacements, suppressions de lignes.
    awk
    Traitement par colonnes, conditions et calculs.
    && / ||
    Exécuter la suite si succès / si échec.
    Substitution de commande
    $(cmd) est remplacé par la sortie de cmd.

    🧠 Quiz : as-tu tout retenu ?

    1. Quel est le numéro de la sortie d'erreur ?
    0 = stdin, 1 = stdout, 2 = stderr.
    2. Quelle différence entre > et >> ?
    > remplace le contenu, >> l'allonge.
    3. Comment masquer uniquement les messages d'erreur d'une commande ?
    > /dev/null masquerait au contraire les résultats et garderait les erreurs.
    4. Pourquoi met-on sort avant uniq -c ?
    Sans tri, deux lignes identiques séparées seraient comptées séparément.
    5. Que fait grep -v '^#' fichier.conf ?
    -v inverse la sélection ; ^# = « commence par # ». Le fichier n'est pas modifié.
    6. Dans awk '{print $3}', que représente $3 ?
    awk découpe chaque ligne en champs numérotés. Les apostrophes empêchent le shell d'interpréter $3.
    7. sudo apt update && sudo apt upgrade : quand upgrade est-il lancé ?
    && enchaîne en cas de succès (code de retour 0).
    8. Que contient notes.txt après sort notes.txt > notes.txt ?
    Le shell ouvre (et vide) notes.txt pour la redirection avant que sort ne le lise.

    💬 Questions fréquentes

    Les questions qui reviennent le plus souvent sur ce module, avec leurs réponses.

    Comment taper le caractère | sur un clavier AZERTY ?

    AltGr + 6 (la touche du tiret). Sur un Mac : Alt + Maj + L. Pour les autres symboles utiles : ~ = AltGr + 2 puis Espace, { } = AltGr + 4 / +, [ ] = AltGr + 5 / °.

    sudo echo "texte" > /etc/fichier donne « Permission non accordée »

    La redirection > est faite par ton shell, sans droits root ; seul echo tourne avec sudo. La solution : echo "texte" | sudo tee /etc/fichier (ou sudo tee -a pour ajouter). Ici, c'est tee qui écrit, avec les droits de root.

    Mon pipeline ne renvoie rien

    Démonte-le : exécute la première commande seule, puis ajoute les maillons un par un avec ↑. Le coupable est souvent un séparateur mal choisi dans cut (espace contre tabulation) ou un grep sensible aux majuscules (essaie -i).
