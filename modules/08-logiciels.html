    Paquets et dépôts

    Paquet
    Une archive (.deb sur Ubuntu) qui contient un logiciel, ses fichiers de configuration et la liste de ses dépendances.
    Dépendance
    Un autre paquet indispensable au fonctionnement (une bibliothèque, par exemple). Le gestionnaire les installe automatiquement.
    Dépôt
    Un serveur qui héberge des milliers de paquets, signés numériquement par la distribution.
    Gestionnaire de paquets
    L'outil qui télécharge, vérifie, installe et met à jour : apt sur Debian et Ubuntu, dnf sur Fedora, pacman sur Arch.

    Les dépôts d'Ubuntu

    ComposantContenuMaintenu par
    mainLogiciels libres essentiels, supportés officiellementCanonical

    restrictedPilotes propriétaires indispensables (cartes graphiques…)Canonical

    Sur Ubuntu 24.04, la liste des dépôts est dans /etc/apt/sources.list.d/ubuntu.sources :

    user@ubuntu:~$ cat /etc/apt/sources.list.d/ubuntu.sources
Types: deb
URIs: http://fr.archive.ubuntu.com/ubuntu/
Suites: noble noble-updates noble-backports
Components: main restricted universe multiverse
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg

Types: deb
URIs: http://security.ubuntu.com/ubuntu/
Suites: noble-security
...

    Signed-By indique la clé qui garantit l'authenticité des paquets : si un paquet a été modifié en route, apt refuse de l'installer.

    apt ou apt-get ?

    apt est la version moderne et conviviale (barre de progression, couleurs) : idéale au terminal. apt-get et apt-cache, plus anciens, ont une sortie stable : on les préfère dans les scripts. Les deux utilisent les mêmes dépôts et la même base.

    Sous le capot : dpkg

    apt télécharge et résout les dépendances ; c'est dpkg qui installe réellement les fichiers .deb. Il reste très utile pour interroger le système :

    user@ubuntu:~$ dpkg -l | grep openssh              # le paquet est-il installé ?
ii  openssh-client  1:9.6p1-3ubuntu13  amd64  secure shell (SSH) client
user@ubuntu:~$ dpkg -L btop | head -3              # quels fichiers a-t-il installés ?
user@ubuntu:~$ dpkg -S /usr/bin/ls                    # à quel paquet appartient ce fichier ?
coreutils: /usr/bin/ls
user@ubuntu:~$ sudo apt install ./logiciel.deb       # installer un .deb téléchargé (avec ses dépendances)

    Dans dpkg -l, les deux lettres ii signifient « souhaité : installé, état : installé ». rc désigne un paquet supprimé dont il reste la configuration (à nettoyer avec purge).

    PPA et dépôts tiers

    Certains logiciels ne sont pas dans les dépôts officiels, ou dans une version trop ancienne. Deux solutions :

    🧑‍🔧

    Un PPA

    Personal Package Archive : un dépôt hébergé sur Launchpad par un développeur ou une équipe.

    sudo add-apt-repository ppa:auteur/nom
    🏢

    Le dépôt de l'éditeur

    Docker, Google Chrome, VS Code… publient leur propre dépôt, avec leur clé de signature.

    /etc/apt/sources.list.d/
    Un dépôt tiers = une confiance totale

    Les paquets s'installent avec les droits de root : ajouter un dépôt, c'est autoriser son auteur à exécuter n'importe quoi sur ta machine, à chaque mise à jour. N'ajoute que des dépôts d'éditeurs reconnus, et retire ceux qui ne servent plus : sudo add-apt-repository --remove ppa:auteur/nom.

    user@ubuntu:~$ snap list                              # les snaps installés (firefox en fait partie)
user@ubuntu:~$ snap find "video editor"
user@ubuntu:~$ sudo snap install vlc
user@ubuntu:~$ sudo snap refresh                      # forcer la mise à jour maintenant

user@ubuntu:~$ sudo apt install flatpak               # flatpak n'est pas installé par défaut sur Ubuntu
user@ubuntu:~$ flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
user@ubuntu:~$ flatpak install flathub org.gimp.GIMP

    La logithèque graphique d'Ubuntu (App Center) propose à la fois des snaps et des paquets deb : regarde la source indiquée sur la fiche de chaque logiciel.

    Dernier recours : compiler depuis les sources

    Quand un logiciel n'existe dans aucun format, on peut le construire à partir de son code source. La recette classique :

    user@ubuntu:~$ sudo apt install build-essential        # compilateur gcc, make…
user@ubuntu:~$ tar xf logiciel-1.2.tar.gz && cd logiciel-1.2
user@ubuntu:~/logiciel-1.2$ ./configure                   # vérifie l'environnement, prépare la compilation
user@ubuntu:~/logiciel-1.2$ make                          # compile
user@ubuntu:~/logiciel-1.2$ sudo make install              # installe, en général dans /usr/local
    Ce que tu perds

    Un logiciel compilé à la main échappe au gestionnaire de paquets : pas de mises à jour automatiques (donc pas de correctifs de sécurité), et une désinstallation parfois difficile. Lis toujours le fichier README ou INSTALL du projet, et garde ce choix pour les vrais cas particuliers.

    Les mises à jour automatiques

    Ubuntu installe les correctifs de sécurité tout seul, chaque jour, grâce au service unattended-upgrades. Pour vérifier ce qui a été fait :

    user@ubuntu:~$ systemctl status unattended-upgrades | head -3
● unattended-upgrades.service - Unattended Upgrades Shutdown
     Loaded: loaded (/usr/lib/systemd/system/unattended-upgrades.service; enabled; preset: enabled)
user@ubuntu:~$ less /var/log/apt/history.log            # l'historique de toutes les installations
user@ubuntu:~$ ls /var/run/reboot-required 2>/dev/null && echo "Redémarrage nécessaire"

    Une mise à jour du noyau ne prend effet qu'au redémarrage : le fichier /var/run/reboot-required apparaît alors.

    Glossaire du module

    Paquet (.deb)
    Archive d'un logiciel prête à installer, avec ses dépendances déclarées.
    Dépôt
    Serveur de paquets signés.
    apt
    Gestionnaire de paquets de Debian et Ubuntu.
    dpkg
    L'outil bas niveau qui installe les fichiers .deb.
    PPA
    Dépôt personnel hébergé sur Launchpad.
    snap
    Format de Canonical : autonome, isolé, mis à jour automatiquement.

    Format communautaire équivalent, multi-distributions, catalogue Flathub.
    Compilation
    Transformer un code source en programme exécutable.

    Service qui installe automatiquement les correctifs de sécurité.

    🧠 Quiz : as-tu tout retenu ?

    1. Que fait sudo apt update ?
    C'est apt upgrade qui installe les nouvelles versions.
    2. Différence entre remove et purge ?
    Les fichiers de ton dossier personnel ne sont jamais touchés par apt.
    3. Comment savoir à quel paquet appartient /usr/bin/ls ?
    dpkg -S cherche le paquet propriétaire d'un fichier (ici coreutils).
    4. Quel format se met à jour automatiquement en arrière-plan ?
    snapd vérifie et applique les mises à jour plusieurs fois par jour.
    5. Pourquoi être prudent avec les PPA ?
    Ajouter un dépôt, c'est autoriser son auteur à modifier ton système à chaque mise à jour.
    6. Comment installer proprement un fichier logiciel.deb téléchargé ?
    Le ./ indique un fichier local ; apt installe aussi ses dépendances.
    7. Que fait sudo apt autoremove ?
    Le cache se vide avec sudo apt clean.
    8. Inconvénient principal d'un logiciel compilé depuis les sources ?
    C'est à toi de surveiller et d'appliquer les correctifs.

    💬 Questions fréquentes

    Les questions qui reviennent le plus souvent sur ce module, avec leurs réponses.

    « Impossible d'obtenir le verrou /var/lib/dpkg/lock-frontend »

    Un autre programme utilise déjà le gestionnaire de paquets : souvent les mises à jour automatiques, juste après le démarrage, ou une autre fenêtre de terminal. Attends quelques minutes et réessaie. Ne supprime jamais le fichier de verrou à la main : tu risquerais de corrompre la base des paquets.

    « Paquets cassés » ou « dépendances non satisfaites »

    Souvent après une installation interrompue. Essaie dans l'ordre : sudo apt --fix-broken install, puis sudo dpkg --configure -a, puis sudo apt update && sudo apt upgrade. Si un PPA est en cause, retire-le.

    Pourquoi Firefox est-il un snap sur Ubuntu ?

    Depuis Ubuntu 22.04, Mozilla et Canonical distribuent Firefox en snap : les mises à jour arrivent directement de Mozilla, le jour de leur sortie, et le navigateur est isolé du système. Le prix à payer est un premier démarrage un peu plus lent.
