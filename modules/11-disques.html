    Disques, partitions et systèmes de fichiers

    Pour qu'un disque serve à ranger des fichiers, il passe toujours par trois étapes :

    💽
    Disque brut/dev/sdb
    →
    🔪
    Partitionnerfdisk, parted → /dev/sdb1
    →
    🧱
    Formatermkfs.ext4 : un système de fichiers
    →
    📌
    Montermount → /mnt/data
    Partition
    Une zone du disque, utilisée comme un disque indépendant. La liste des partitions est la table de partitions : GPT (moderne) ou MBR (ancienne, limitée à 2 To et 4 partitions principales).
    Système de fichiers
    La structure qui organise les fichiers dans une partition : ext4 (le standard de Linux), xfs et btrfs (autres choix Linux), vfat (clés USB, partition EFI), ntfs et exfat (compatibles avec Windows).
    Point de montage
    Le dossier où le contenu d'une partition apparaît dans l'arbre unique (module 02). Pas de lettre D: sous Linux.

    Le nom des disques

    NomDésigne
    /dev/sda, /dev/sdb…Disques SATA, SCSI ou USB, dans l'ordre de détection (a = le premier)
    /dev/sda1, /dev/sda2Les partitions du disque sda
    /dev/nvme0n1, /dev/nvme0n1p1Disque SSD NVMe et sa première partition (p1)
    /dev/vdaDisque virtuel de certaines VM (KVM, cloud). Sous VirtualBox, c'est sda
    /dev/sr0Le lecteur de CD/DVD (même virtuel)
    /dev/loop0…Fichiers utilisés comme des disques : chaque snap installé en monte un (module 08)

    Faire l'inventaire : lsblk

    user@ubuntu:~$ lsblk -e7                          # -e7 : masque les loop des snaps
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda      8:0    0   40G  0 disk
├─sda1   8:1    0    1G  0 part /boot/efi
└─sda2   8:2    0   39G  0 part /
sr0     11:0    1 1024M  0 rom
user@ubuntu:~$ lsblk -f /dev/sda                  # -f : systèmes de fichiers, étiquettes, UUID
NAME   FSTYPE FSVER LABEL UUID                                 FSAVAIL FSUSE% MOUNTPOINTS
sda
├─sda1 vfat   FAT32       4A1C-9F2E                             1,1G     1% /boot/efi
└─sda2 ext4   1.0         0b3e5c8a-7f41-4d2c-9a55-2e1f7d6c8b90   26,3G    27% /

    TYPE distingue les disques (disk) des partitions (part), et MOUNTPOINTS indique où chaque partition est branchée. Pour plus de détails : sudo fdisk -l (taille exacte, type de table) et sudo blkid (UUID de chaque partition).

    La règle d'or des disques

    Avant toute commande qui écrit sur un disque (fdisk, mkfs…), relance lsblk et vérifie deux fois le nom. mkfs sur /dev/sda au lieu de /dev/sdb efface ton système en une seconde, sans confirmation. Dans ce module, on ne touche qu'à un disque ajouté exprès : la VM n'y risque rien.

    Ajouter un disque virtuel

    1. Éteindre la VM

      Un vrai arrêt (sudo poweroff), pas une mise en veille.

    2. Configuration › Stockage

      Sélectionne le Contrôleur : SATA, puis l'icône de disque dur avec un « + » (Ajouter un disque dur).

    3. Créer

      Type VDI, dynamiquement alloué, taille 2 Go, nom data. Choisis-le, puis OK.

    4. Démarrer et vérifier

      lsblk affiche un nouveau disque sdb de 2G, sans partition. C'est notre terrain de jeu.

    Partitionner avec fdisk

    fdisk est interactif : chaque commande tient en une lettre, et rien n'est écrit sur le disque avant w. En cas de doute, q quitte sans rien changer.

    user@ubuntu:~$ sudo fdisk /dev/sdb
Commande (m pour l'aide) : g                # nouvelle table de partitions GPT
Une nouvelle étiquette de disque GPT a été créée.
Commande (m pour l'aide) : n                # nouvelle partition
Numéro de partition (1-128, 1 par défaut) : ⏎        # Entrée = valeur par défaut
Premier secteur (2048-4194270, 2048 par défaut) : ⏎
Dernier secteur, +/-secteurs ou +/-taille{K,M,G,T,P} (2048-4194270, 4192255 par défaut) : ⏎
Une nouvelle partition 1 de type « Linux filesystem » et de taille 2 GiB a été créée.
Commande (m pour l'aide) : p                # afficher le résultat avant d'écrire
Commande (m pour l'aide) : w                # écrire et quitter
La table de partitions a été altérée.

    Pour une partition plus petite, réponds par exemple +500M à la question du dernier secteur. Alternative non interactive, pratique dans les scripts : sudo parted /dev/sdb --script mklabel gpt mkpart data ext4 1MiB 100%.

    Formater avec mkfs

    user@ubuntu:~$ sudo mkfs.ext4 -L data /dev/sdb1       # -L : une étiquette lisible
mke2fs 1.47.0 (5-Feb-2023)
Création d'un système de fichiers avec 523776 blocs de 4k et 131072 i-noeuds
UUID de système de fichiers=8cd9384e-8443-4aa8-ba1b-296f168e54fc
…
Écriture des superblocs et de l'information de comptabilité du système de fichiers : complété

    Attention : on formate la partition (sdb1), pas le disque (sdb). Le formatage crée un système de fichiers vide… et efface tout ce qui se trouvait sur la partition. Pour une clé USB à partager avec Windows : sudo mkfs.exfat.

    Monter avec mount

    user@ubuntu:~$ sudo mkdir /mnt/data                     # le point de montage : un dossier vide
user@ubuntu:~$ sudo mount /dev/sdb1 /mnt/data
user@ubuntu:~$ df -h /mnt/data
Sys. de fichiers Taille Utilisé Dispo Uti% Monté sur
/dev/sdb1          2,0G     24K  1,8G   1% /mnt/data
user@ubuntu:~$ ls /mnt/data
lost+found                                    # dossier créé par mkfs, pour les réparations
user@ubuntu:~$ sudo chown $USER: /mnt/data               # la racine du disque appartient à root : on te la donne
user@ubuntu:~$ sudo umount /mnt/data                    # démonter (sans « n » : umount)
    « target is busy » / « la cible est actuellement utilisée »

    On ne peut pas démonter une partition utilisée : un terminal dont le dossier courant est dedans, un fichier ouvert… Fais cd ~, ferme ce qui l'utilise, puis recommence. sudo lsof /mnt/data liste les coupables. Une clé USB s'éjecte de la même façon : démonter avant de débrancher, sinon des données encore en mémoire risquent de ne jamais être écrites.

    Sur le bureau, les clés USB sont montées automatiquement dans /media/user/NOM. findmnt affiche tous les montages en cours, sous forme d'arbre.

    Monter au démarrage : /etc/fstab

    Un montage fait avec mount disparaît au redémarrage. Pour le rendre permanent, on décrit la partition dans /etc/fstab (file systems table), lu à chaque démarrage. On l'identifie par son UUID : contrairement à sdb1, il ne change pas si l'ordre des disques change.

    user@ubuntu:~$ sudo blkid /dev/sdb1
/dev/sdb1: LABEL="data" UUID="8cd9384e-8443-4aa8-ba1b-296f168e54fc" BLOCK_SIZE="4096" TYPE="ext4" PARTUUID="60dbf250-…"
user@ubuntu:~$ sudo cp /etc/fstab /etc/fstab.bak              # toujours une sauvegarde
user@ubuntu:~$ sudo nano /etc/fstab
    # <périphérique>                         <point de montage> <type> <options>        <dump> <fsck>
UUID=8cd9384e-8443-4aa8-ba1b-296f168e54fc  /mnt/data   ext4   defaults,nofail  0  2
    ChampSens
    UUID=…Quelle partition (copie l'UUID donné par blkid, sans les guillemets)
    /mnt/dataOù la monter (le dossier doit exister)
    ext4Son système de fichiers
    defaults,nofailOptions : réglages standard, et ne pas bloquer le démarrage si le disque est absent
    0Ancienne sauvegarde dump : toujours 0
    2Ordre de vérification au démarrage : 1 pour /, 2 pour les autres, 0 pour jamais
    user@ubuntu:~$ sudo findmnt --verify                  # relit fstab et signale les erreurs
user@ubuntu:~$ sudo systemctl daemon-reload             # systemd transforme fstab en unités (module 10)
user@ubuntu:~$ sudo mount -a                         # monte tout ce qui est dans fstab : silence = succès
user@ubuntu:~$ findmnt /mnt/data
TARGET    SOURCE    FSTYPE OPTIONS
/mnt/data /dev/sdb1 ext4   rw,relatime
    Une faute dans fstab peut bloquer le démarrage

    Une ligne fausse (UUID mal copié, dossier inexistant) et la machine s'arrête au démarrage en mode d'urgence. Pour l'éviter : sauvegarde, nofail sur les disques secondaires, et toujours sudo mount -a avant de redémarrer : s'il affiche une erreur, corrige tout de suite. Si c'est déjà arrivé : au mode d'urgence, entre le mot de passe, nano /etc/fstab, commente la ligne fautive avec #, puis reboot.

    df : la carte

    « Disk free » : remplissage de chaque système de fichiers. Répond à : quel disque est plein ?

    🔦

    du : la lampe torche

    « Disk usage » : poids des dossiers. Répond à : qui le remplit ? À combiner avec sort -h.

    🧭

    ncdu : l'explorateur

    sudo apt install ncdu, puis sudo ncdu / : on navigue avec les flèches, triés par taille. d supprime, q quitte.

    Faire le ménage sans risque

    user@ubuntu:~$ sudo apt autoremove                      # dépendances devenues inutiles, vieux noyaux
user@ubuntu:~$ sudo apt clean                           # vide le cache des paquets téléchargés
user@ubuntu:~$ sudo journalctl --vacuum-size=100M         # réduit le journal de systemd à 100 Mo
user@ubuntu:~$ du -sh ~/.cache ~/Téléchargements             # et chez toi : cache et vieux téléchargements
    Jamais de rm au hasard dans /var ou /usr

    Les fichiers de /var/lib (bases des paquets, des snaps…) ou de /usr ne se suppriment pas à la main : passe toujours par l'outil qui les gère (apt, snap, journalctl). Et un journal énorme dans /var/log se vide avec sudo truncate -s 0 fichier.log, pas avec rm : le programme qui écrit dedans le garde ouvert.

    Le swap : la mémoire de secours

    Quand la mémoire vive (RAM) est pleine, le noyau déplace les données les moins utilisées vers le swap, une zone du disque. Le système ralentit au lieu de planter. Ubuntu utilise un fichier d'échange, /swap.img, plutôt qu'une partition.

    user@ubuntu:~$ free -h
               total       utilisé      libre     partagé tamp/cache   disponible
Mem:           3,8Gi       1,9Gi       480Mi        52Mi       1,7Gi       1,9Gi
Échange:       3,8Gi       120Mi       3,7Gi
user@ubuntu:~$ swapon --show
NAME      TYPE SIZE   USED PRIO
/swap.img file 3,8G 120,5M   -2

    Lis la colonne disponible, pas libre : Linux utilise la mémoire inoccupée comme cache disque (tamp/cache), et la rend dès qu'un programme en a besoin. Un peu de swap utilisé est normal ; un swap plein et une machine qui rame signifient qu'il manque de la RAM (dans une VM : augmente-la dans la configuration).

    Aller plus loin : LVM

    Une partition a une taille fixe, difficile à changer. LVM (Logical Volume Manager) ajoute une couche de souplesse : on regroupe des disques dans un grand réservoir, puis on y découpe des volumes qu'on peut agrandir à chaud, même sur plusieurs disques.

    💽
    Volumes physiques (PV)/dev/sdb1, /dev/sdc1…
    →
    🪣
    Groupe de volumes (VG)le réservoir commun
    →
    📦
    Volumes logiques (LV)formatés et montés comme des partitions
    user@ubuntu:~$ sudo pvs; sudo vgs; sudo lvs                 # l'état de chaque couche
user@ubuntu:~$ sudo lvextend -r -l +100%FREE /dev/ubuntu-vg/ubuntu-lv   # agrandir le volume ET son système de fichiers
    Le piège classique d'Ubuntu Server

    Ubuntu Server installe le système sur LVM, mais ne donne au volume racine qu'une partie du disque. Si df -h / montre un disque de 100 Go à moitié vide et une racine pleine de 50 Go, la commande lvextend ci-dessus récupère tout l'espace libre du groupe. Ubuntu Desktop, lui, n'utilise pas LVM par défaut.

    💬 Questions fréquentes

    Les questions qui reviennent le plus souvent sur ce module, avec leurs réponses.

    Pourquoi lsblk affiche-t-il plein de loop ?

    Chaque snap installé (module 08) est un fichier compressé monté comme un disque en lecture seule : ce sont les loop0, loop1… Ils sont normaux. lsblk -e7 les masque (7 est le numéro de périphérique des loop) ; df -x squashfs fait de même pour df.

    Après une erreur dans fstab, la machine démarre en « mode d'urgence » (emergency mode)

    Entre le mot de passe de ton utilisateur… ou de root si on te le demande. La racine peut être en lecture seule : mount -o remount,rw /. Puis nano /etc/fstab, ajoute un # devant la ligne fautive (ou restaure /etc/fstab.bak), et reboot. Dans une VM, restaurer l'instantané pris avant la mission est encore plus rapide.

    df et du ne donnent pas le même total : lequel croire ?

    Les deux. df interroge le système de fichiers, du additionne les fichiers qu'il peut lire. Les écarts viennent des dossiers que du ne peut pas lire sans sudo, de l'espace réservé à root (5 % sur ext4), et des fichiers supprimés mais encore ouverts par un programme, qui occupent toujours de la place jusqu'à sa fermeture.
