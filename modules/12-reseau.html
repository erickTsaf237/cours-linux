    Les quatre notions du réseau

    Quand tu ouvres https://ubuntu.com, ta machine répond en une fraction de seconde à quatre questions :

    🏠
    Qui suis-je ?mon adresse IP : 10.0.2.15
    →
    📖
    Où est ubuntu.com ?le DNS : 185.125.190.20
    →
    🚪
    Par où sortir ?la passerelle : 10.0.2.2
    →
    🔢
    Quel service ?le port 443 (HTTPS)
    Adresse IP
    L'adresse d'une machine sur le réseau. En IPv4 : quatre nombres de 0 à 255 (192.168.1.20). En IPv6, plus longue : 2001:db8::1.
    Masque (/24)
    Indique quelle partie de l'adresse désigne le réseau. 192.168.1.20/24 : les 24 premiers bits (192.168.1) sont le réseau, le dernier nombre la machine. Toutes les machines en 192.168.1.x se parlent directement.
    Passerelle
    Le routeur par lequel passe tout ce qui sort du réseau local : ta box, ou le routeur virtuel de VirtualBox.
    DNS
    L'annuaire d'Internet : il traduit un nom (ubuntu.com) en adresse IP.
    DHCP
    Le service, souvent dans la box, qui distribue automatiquement adresse, masque, passerelle et DNS aux machines qui arrivent.
    Port
    Un numéro de 0 à 65535 qui désigne un service sur une machine : 22 pour SSH, 80 pour HTTP, 443 pour HTTPS, 53 pour le DNS.
    TCP / UDP
    Deux façons de transporter les données : TCP vérifie que tout arrive, dans l'ordre (web, SSH) ; UDP envoie sans vérifier, plus vite (DNS, vidéo, jeux).
    Les adresses privées

    Trois plages sont réservées aux réseaux locaux et ne circulent jamais sur Internet : 10.x.x.x, 172.16.x.x à 172.31.x.x et 192.168.x.x. Ta box traduit ces adresses en une seule adresse publique (c'est le NAT). Et 127.0.0.1, alias localhost, désigne toujours… la machine elle-même.

    Ton adresse et ta route : ip

    inet 10.0.2.15/24 brd 10.0.2.255 scope global dynamic noprefixroute enp0s3

user@ubuntu:~$ ip -br a                             # -br : la version courte
lo               UNKNOWN        127.0.0.1/8 ::1/128
enp0s3           UP             10.0.2.15/24 fe80::a00:27ff:fe3a:5c9e/64
user@ubuntu:~$ ip route

10.0.2.0/24 dev enp0s3 proto kernel scope link src 10.0.2.15 metric 100
    Ce que tu lisSignification
    loL'interface de bouclage : la machine qui se parle à elle-même (127.0.0.1)
    enp0s3La carte réseau (Ethernet, bus PCI 0, emplacement 3). Une carte Wi-Fi s'appellerait wlp2s0 par exemple
    state UPLe câble (virtuel) est branché et l'interface active
    link/ether 08:00:27:…L'adresse MAC, gravée dans la carte (08:00:27 = carte VirtualBox)
    inet 10.0.2.15/24L'adresse IPv4 et son masque. dynamic : reçue par DHCP
    default via 10.0.2.2La route par défaut : tout ce qui n'est pas local part vers la passerelle 10.0.2.2
    Et ifconfig ?

    Tu le croiseras dans de vieux tutoriels. Il vient du paquet net-tools, abandonné et absent d'Ubuntu par défaut. ip le remplace : ip a pour ifconfig, ip route pour route -n, ss pour netstat.

    Les noms : DNS, dig et /etc/hosts

    user@ubuntu:~$ dig +short ubuntu.com                    # la réponse seule
185.125.190.20
185.125.190.21
185.125.190.29
user@ubuntu:~$ dig ubuntu.com                           # la version détaillée
;; ANSWER SECTION:
ubuntu.com.		60	IN	A	185.125.190.20          # A = adresse IPv4, 60 = durée de validité (s)
…
;; Query time: 39 msec
;; SERVER: 127.0.0.53#53(127.0.0.53) (UDP)          # qui a répondu
user@ubuntu:~$ resolvectl status                       # les vrais serveurs DNS utilisés
Link 2 (enp0s3)
    Current Scopes: DNS
Current DNS Server: 10.0.2.3
       DNS Servers: 10.0.2.3

    Pourquoi 127.0.0.53 ? Ubuntu fait passer toutes les questions DNS par un petit service local, systemd-resolved, qui garde les réponses en cache et les transmet aux vrais serveurs (ici 10.0.2.3, celui de VirtualBox). C'est aussi pourquoi /etc/resolv.conf ne contient que nameserver 127.0.0.53 : il ne faut pas le modifier à la main. dig vient du paquet bind9-dnsutils : s'il manque, sudo apt install bind9-dnsutils.

    Le carnet d'adresses local : /etc/hosts

    Avant d'interroger le DNS, Linux lit /etc/hosts. Une ligne ajoutée ici l'emporte : pratique pour donner un nom à une machine du réseau local ou tester un site avant sa mise en ligne.

    127.0.0.1       localhost
127.0.1.1       ubuntu
192.168.1.20    serveur                # ajouté : « ping serveur » fonctionne désormais

    getent hosts serveur affiche ce que le système résout réellement, /etc/hosts compris (contrairement à dig, qui n'interroge que le DNS).

    Diagnostiquer une connexion

    « Internet ne marche pas » cache toujours une étape précise qui casse. On remonte le chemin, du plus proche au plus lointain :

    1. L'interface est-elle active, avec une adresse ?

      ip -br a : UP et une adresse en inet. Sinon : câble, Wi-Fi, DHCP.

    2. La passerelle répond-elle ?

      ping -c 3 10.0.2.2 (l'adresse donnée par ip route). Sinon : problème de réseau local.

    3. Internet répond-il ?

      ping -c 3 1.1.1.1 : une adresse IP, donc sans DNS. Sinon : la box ou le fournisseur d'accès.

    4. Le DNS répond-il ?

      ping -c 3 ubuntu.com. Si l'étape 3 marche mais pas celle-ci : c'est le DNS (resolvectl status).

    5. Le service répond-il ?

      La machine répond mais pas le site : port fermé, pare-feu, service arrêté (ss, ufw, systemctl).

    user@ubuntu:~$ ping -c 3 ubuntu.com                     # -c 3 : trois essais, puis s'arrête
PING ubuntu.com (185.125.190.20) 56(84) bytes of data.
64 bytes from website-content-cache-1.ps5.canonical.com (185.125.190.20): icmp_seq=1 ttl=53 time=26.9 ms
64 bytes from website-content-cache-1.ps5.canonical.com (185.125.190.20): icmp_seq=2 ttl=53 time=30.6 ms
64 bytes from website-content-cache-1.ps5.canonical.com (185.125.190.20): icmp_seq=3 ttl=53 time=27.2 ms

--- ubuntu.com ping statistics ---
3 packets transmitted, 3 received, 0% packet loss, time 2004ms
rtt min/avg/max/mdev = 26.852/28.196/30.566/1.680 ms
user@ubuntu:~$ ping -c 1 nexistepas.invalid
ping: nexistepas.invalid: Nom ou service inconnu          # le nom n'existe pas

    Sans -c, ping continue jusqu'à Ctrl+C. Le time mesure l'aller-retour : quelques millisecondes en local, 20 à 100 ms vers Internet. Attention : certains serveurs ignorent volontairement le ping ; pas de réponse ne veut donc pas toujours dire « éteint ». Et si le DNS lui-même est injoignable, le message devient Échec temporaire dans la résolution du nom.

    Qui écoute ? ss

    user@ubuntu:~$ ss -tuln                    # t TCP, u UDP, l en écoute (listen), n numéros bruts
Netid State  Recv-Q Send-Q Local Address:Port Peer Address:Port
udp   UNCONN 0      0         127.0.0.54:53        0.0.0.0:*
udp   UNCONN 0      0      127.0.0.53%lo:53        0.0.0.0:*
tcp   LISTEN 0      4096   127.0.0.53%lo:53        0.0.0.0:*
tcp   LISTEN 0      4096         0.0.0.0:22        0.0.0.0:*
tcp   LISTEN 0      4096       127.0.0.1:631       0.0.0.0:*
user@ubuntu:~$ sudo ss -tlnp                          # p : quel programme (sudo pour tout voir)

    L'adresse d'écoute compte autant que le port : 127.0.0.1:631 (l'impression, CUPS) n'est joignable que depuis la machine elle-même, alors que 0.0.0.0:22 accepte les connexions venues de toutes les interfaces. C'est ce second cas que le pare-feu doit surveiller. Le port 22 n'apparaît que si le serveur SSH est installé (module 13).

    Le chemin complet : traceroute

    user@ubuntu:~$ sudo apt install traceroute
user@ubuntu:~$ traceroute -n 1.1.1.1                     # chaque ligne : un routeur traversé
 1  10.0.2.2  0.320 ms  0.288 ms  0.270 ms
 2  * * *
 3  * * *

    Dans une VM en mode NAT, seule la première étape apparaît : VirtualBox ne relaie pas les réponses des routeurs suivants. Sur une vraie machine, tu verrais défiler ta box, les routeurs de ton fournisseur, puis ceux d'Internet. Pour tester un site web : curl -I https://ubuntu.com affiche juste les en-têtes de la réponse (sudo apt install curl si besoin).

    Configurer : NetworkManager et Netplan

    🖥️

    Ubuntu Desktop

    NetworkManager gère le réseau : l'icône en haut à droite, les Paramètres › Réseau, ou nmcli dans le terminal.

    🗄️

    Ubuntu Server

    Netplan : un fichier YAML dans /etc/netplan/, appliqué par systemd-networkd. Pas d'interface graphique.

    user@ubuntu:~$ nmcli device status
DEVICE  TYPE      STATE                   CONNECTION
enp0s3  ethernet  connecté                Connexion filaire 1
lo      loopback  connecté (en externe)   lo
user@ubuntu:~$ nmcli connection show                    # les profils de connexion enregistrés
user@ubuntu:~$ nmcli device wifi list                   # sur une vraie machine : les réseaux Wi-Fi visibles

    Une adresse fixe avec Netplan (serveur)

    Un serveur doit garder la même adresse pour qu'on le retrouve. On remplace le DHCP par une adresse statique :

    network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: false
      addresses: [192.168.1.50/24]          # l'adresse fixe et son masque
      routes:
        - to: default
          via: 192.168.1.1                 # la passerelle (la box)
      nameservers:
        addresses: [1.1.1.1, 9.9.9.9]      # les serveurs DNS
    user@serveur:~$ sudo netplan try          # applique, et annule tout seul après 120 s sans confirmation
user@serveur:~$ sudo netplan apply        # applique définitivement
    YAML : les espaces comptent

    L'indentation se fait avec des espaces, jamais de tabulation, et chaque niveau doit être aligné. Une erreur et netplan refuse le fichier en indiquant la ligne. Utilise toujours netplan try sur une machine distante : si tu perds la connexion, la configuration précédente revient seule. Le fichier doit aussi rester lisible par root seulement (sudo chmod 600), sinon netplan le signale.

    Le réseau de ta machine virtuelle

    Dans VirtualBox, Configuration › Réseau choisit comment la VM est reliée au monde. Le mode change son adresse… et qui peut la joindre.

    ModeAdresse typiqueLa VM accède à InternetOn peut joindre la VM depuis…
    NAT (par défaut)10.0.2.15✅Personne, sauf avec une redirection de port (module 13)
    Accès par pontune adresse de ta box, ex. 192.168.1.37✅Tout le réseau local, comme une vraie machine
    Réseau privé hôte192.168.56.x❌Ton ordinateur uniquement
    Réseau NAT10.0.2.x✅Les autres VM du même réseau NAT

    En NAT, VirtualBox joue lui-même le rôle de box : passerelle 10.0.2.2, DNS 10.0.2.3, et un DHCP qui donne toujours 10.0.2.15. C'est pour cela que toutes les VM en NAT ont la même adresse sans se gêner : chacune a son propre petit réseau privé.

    Le pare-feu : ufw

    Le pare-feu de Linux est intégré au noyau (netfilter, réglé par nftables ou l'ancien iptables). Ses règles sont puissantes mais verbeuses ; Ubuntu fournit ufw (Uncomplicated FireWall) qui les écrit pour toi. Il est installé mais désactivé par défaut.

    user@ubuntu:~$ sudo ufw status
État : inactif
user@ubuntu:~$ sudo ufw default deny incoming             # 1. refuser tout ce qui entre
La stratégie par défaut pour le sens « incoming » a été remplacée par « deny »
(veillez à mettre à jour vos règles en conséquence)
user@ubuntu:~$ sudo ufw default allow outgoing            # 2. autoriser tout ce qui sort
user@ubuntu:~$ sudo ufw allow ssh                         # 3. ouvrir le nécessaire (22/tcp)
Les règles ont été mises à jour
Les règles ont été mises à jour (IPv6)
user@ubuntu:~$ sudo ufw allow 80/tcp                      #    un serveur web, par exemple
user@ubuntu:~$ sudo ufw enable                            # 4. activer (et à chaque démarrage)
Le pare-feu est actif et lancé au démarrage du système
user@ubuntu:~$ sudo ufw status verbose
État : actif
Journalisation : on (low)
Par défaut : deny (incoming), allow (outgoing), disabled (routed)

    Sur une machine distante : SSH d'abord

    Si tu administres un serveur par SSH, sudo ufw allow ssh doit être fait avant sudo ufw enable. Dans l'autre ordre, le pare-feu coupe ta propre connexion : il ne reste plus qu'à aller devant la machine… ou à passer par la console de l'hébergeur.

    CommandeEffet
    sudo ufw allow 443/tcpOuvre un port pour tout le monde
    sudo ufw allow from 192.168.1.0/24 to any port 22Ouvre SSH au réseau local seulement
    sudo ufw deny 3306Refuse explicitement un port
    sudo ufw limit sshAutorise SSH mais bloque une adresse qui tente plus de 6 connexions en 30 s
    sudo ufw status numberedListe les règles avec un numéro
    sudo ufw delete 2 ou sudo ufw delete allow 80/tcpSupprime une règle (par numéro ou en la répétant)
    sudo ufw app listProfils fournis par les logiciels installés (OpenSSH, Apache…)
    sudo ufw disable / sudo ufw resetDésactive / efface toutes les règles

    Pour vérifier depuis l'extérieur, nmap (sudo apt install nmap) liste les ports qui répondent : nmap 192.168.1.20. À n'utiliser que sur tes propres machines : scanner celles des autres sans autorisation est interdit.

    Glossaire du module

    Adresse IP
    Adresse d'une machine sur le réseau (ip a).
    Masque / CIDR
    Taille du réseau local : /24 = 256 adresses.
    Passerelle
    Routeur de sortie du réseau local (ip route).
    DNS
    Traduit les noms en adresses (dig, resolvectl).
    DHCP
    Distribue automatiquement les réglages réseau.
    Port
    Numéro d'un service sur une machine (22, 80, 443…).
    NAT
    Partage d'une adresse publique entre plusieurs machines privées.
    Netplan / NetworkManager
    Outils de configuration du réseau sur Ubuntu Server / Desktop.
    Pare-feu
    Filtre les connexions entrantes et sortantes (ufw).

    🧠 Quiz : as-tu tout retenu ?

    1. Quelle commande affiche l'adresse IP de ta machine ?
    ip a (address) liste les interfaces et leurs adresses ; ip route montre la passerelle.
    2. ping 1.1.1.1 fonctionne, mais ping ubuntu.com échoue. Le coupable ?
    Internet répond (l'adresse IP passe), seule la traduction du nom échoue.
    3. Laquelle de ces adresses est privée ?
    Les plages privées : 10.x, 172.16-31.x, 192.168.x.
    4. Dans ss -tuln, un service sur 127.0.0.1:631 est joignable…
    127.0.0.1 = localhost. 0.0.0.0 signifierait « toutes les interfaces ».
    5. Quel port utilise SSH par défaut ?
    80 = HTTP, 443 = HTTPS, 22 = SSH.
    6. Sur un serveur administré à distance, que faire avant sudo ufw enable ?
    Sinon le pare-feu coupe ta propre connexion.
    7. Pourquoi /etc/resolv.conf indique-t-il 127.0.0.53 ?
    resolvectl status montre les vrais serveurs DNS derrière.
    8. Ta VM est en mode NAT. Qui peut s'y connecter sans réglage supplémentaire ?
    La VM peut sortir, mais rien ne peut entrer sans une redirection de port.

    💬 Questions fréquentes

    Les questions qui reviennent le plus souvent sur ce module, avec leurs réponses.

    Pourquoi ma VM a-t-elle l'adresse 10.0.2.15, et pas une adresse comme mon ordinateur ?

    En mode NAT (le mode par défaut), VirtualBox crée un petit réseau privé rien que pour la VM, avec sa propre passerelle (10.0.2.2) et son propre DHCP. Pour que la VM reçoive une adresse de ta box, comme une vraie machine, passe-la en Accès par pont dans Configuration › Réseau.

    Le navigateur fonctionne mais ping ne répond pas : c'est normal ?

    Oui, souvent. ping utilise un protocole à part (ICMP) que certains serveurs et pare-feu ignorent volontairement. Pour tester un site web, curl -I https://site est plus fiable : il interroge le vrai service, sur le port 443.

    Faut-il activer ufw sur un Ubuntu Desktop ?

    Un Desktop neuf n'expose aucun service vers l'extérieur, donc le risque est faible. Mais l'activer ne coûte rien et protège le jour où tu installes un service (SSH, serveur web…) : sudo ufw enable suffit, puis tu ouvres au cas par cas. Sur un serveur, c'est indispensable.
