    Du bouton Power au bureau

    Le démarrage d'un ordinateur est une course de relais : chaque étape fait un travail précis, puis passe le témoin à la suivante.

    1. Le firmware (UEFI ou BIOS)

      Programme gravé sur la carte mère. Il teste le matériel, puis cherche un programme de démarrage sur un disque. Les machines récentes utilisent l'UEFI, qui lit la partition /boot/efi ; les plus anciennes, le BIOS.

    2. Le chargeur d'amorçage : GRUB

      Il affiche (parfois) un menu pour choisir le système ou le noyau, puis charge en mémoire le noyau et l'initramfs, qu'il trouve dans /boot.

    3. Le noyau et l'initramfs

      Le noyau prend le contrôle du matériel. L'initramfs est un mini-système en mémoire qui contient de quoi accéder au vrai disque (pilotes, chiffrement…). Une fois la partition racine / montée, le noyau lance le programme n° 1.

    4. systemd, le chef d'orchestre

      Processus n° 1 (PID 1), il démarre tous les services en parallèle selon leurs dépendances, jusqu'à la cible finale : l'écran de connexion graphique.

    user@ubuntu:~$ ls /boot                       # le noyau (vmlinuz) et l'initramfs (initrd.img)
config-6.8.0-45-generic      initrd.img-6.8.0-45-generic  vmlinuz-6.8.0-45-generic
efi  grub  initrd.img  vmlinuz  …
user@ubuntu:~$ uname -r                       # la version du noyau en cours
6.8.0-45-generic
user@ubuntu:~$ ps -p 1 -o pid,comm             # qui porte le numéro 1 ?
    PID COMMAND
      1 systemd

    Combien de temps a pris chaque étape ?

    user@ubuntu:~$ systemd-analyze

    Le menu GRUB

    Quand Ubuntu est le seul système installé, GRUB reste caché. Pour faire apparaître son menu, maintiens Maj (BIOS) ou appuie plusieurs fois sur Échap (UEFI) juste après l'allumage. Le menu permet de choisir un ancien noyau, ou d'entrer dans le mode de dépannage (Advanced options › recovery mode) : précieux quand le système ne démarre plus.

    Ses réglages sont dans /etc/default/grub. Par exemple, pour afficher le menu 5 secondes à chaque démarrage :

    GRUB_DEFAULT=0                    # entrée choisie par défaut (la première)
GRUB_TIMEOUT_STYLE=menu             # « hidden » par défaut : menu caché
GRUB_TIMEOUT=5                    # secondes avant de démarrer
GRUB_CMDLINE_LINUX_DEFAULT="quiet splash"   # options passées au noyau
    user@ubuntu:~$ sudo nano /etc/default/grub
user@ubuntu:~$ sudo update-grub                 # OBLIGATOIRE : régénère /boot/grub/grub.cfg
    Ne jamais modifier grub.cfg à la main

    /boot/grub/grub.cfg est réécrit à chaque mise à jour du noyau. On modifie toujours /etc/default/grub, puis on lance sudo update-grub. Dans une VM, fais un instantané VirtualBox avant : une faute ici peut empêcher le démarrage.

    Les services et systemctl

    Un service (ou démon, daemon en anglais, d'où le « d » final de sshd, systemd…) est un programme qui tourne en arrière-plan, sans fenêtre : il planifie des tâches, gère le réseau, imprime, répond aux connexions SSH… systemctl est la télécommande de systemd pour les piloter.

    user@ubuntu:~$ systemctl status cron
● cron.service - Regular background program processing daemon
     Loaded: loaded (/usr/lib/systemd/system/cron.service; enabled; preset: enabled)
     Active: active (running) since mar. 2026-10-27 09:12:04 CET; 2h 3min ago
       Docs: man:cron(8)
   Main PID: 812 (cron)
      Tasks: 1 (limit: 4598)
     Memory: 1.2M (peak: 2.0M)
     CGroup: /system.slice/cron.service
             └─812 /usr/sbin/cron -f -P

oct. 27 09:12:04 ubuntu systemd[1]: Started cron.service - Regular background program processing daemon.

    Trois informations à lire en priorité : le point (vert : tout va bien, rouge : en échec, blanc : arrêté), la ligne Loaded (enabled : il démarre avec la machine) et la ligne Active (son état actuel). Les dernières lignes viennent du journal. Si la sortie dépasse l'écran, elle s'ouvre dans less : q pour quitter.

    CommandeEffetQuand ?
    sudo systemctl start nomDémarre le serviceMaintenant
    sudo systemctl stop nomL'arrêteMaintenant
    sudo systemctl restart nomL'arrête puis le relanceAprès un changement de configuration
    sudo systemctl reload nomRelit sa configuration sans couper (si le service le permet)Serveur web en production
    sudo systemctl enable nomLe lance à chaque démarragePour toujours
    sudo systemctl disable nomNe le lance plus au démarragePour toujours
    sudo systemctl enable --now nomenable + start en une foisLe plus courant
    start ≠ enable

    start agit sur maintenant, enable sur les prochains démarrages. Les deux sont indépendants : un service peut être démarré sans être activé (il ne reviendra pas après un redémarrage), ou activé sans être démarré (il attendra le prochain démarrage). systemctl is-active nom et systemctl is-enabled nom répondent en un mot.

    user@ubuntu:~$ systemctl list-units --type=service             # services chargés en ce moment
user@ubuntu:~$ systemctl list-units --type=service --state=failed   # ceux en échec
user@ubuntu:~$ systemctl list-unit-files --type=service        # tous les services installés, activés ou non
    Pas besoin d'écrire « .service »

    systemctl status cron et systemctl status cron.service sont équivalents. Et la touche Tab complète les noms de services.

    Cibles, arrêt et redémarrage

    Une cible (target) est un groupe de services à atteindre : c'est la « destination » du démarrage.

    🖥️

    graphical.target

    Tout le système, avec l'interface graphique. La cible par défaut d'Ubuntu Desktop.

    ⌨️

    multi-user.target

    Tout le système, en mode texte seulement. Celle des serveurs.

    🩺

    rescue.target

    Mode de secours : le strict minimum, pour réparer.

    user@ubuntu:~$ systemctl get-default
graphical.target
user@ubuntu:~$ sudo systemctl reboot                     # redémarrer (ou simplement : sudo reboot)
user@ubuntu:~$ sudo systemctl poweroff                   # éteindre (ou : sudo poweroff)

    sudo systemctl set-default multi-user.target ferait démarrer la machine en mode texte (sans bureau) ; graphical.target rétablit le bureau. Pratique pour transformer une VM en petit serveur qui consomme moins de mémoire.

    Les journaux avec journalctl

    systemd recueille dans un journal central les messages du noyau, des services et du démarrage. C'est le premier endroit où regarder quand quelque chose ne marche pas.

    CommandeAffiche
    journalctl -u cronLes messages d'un seul service
    journalctl -u cron -fLes mêmes, en direct (Ctrl + C pour arrêter), comme tail -f
    journalctl -bTout depuis le dernier démarrage (-b -1 : le démarrage précédent)
    journalctl -p err -bSeulement les erreurs (et pire) de ce démarrage
    journalctl --since "1 hour ago"La dernière heure (accepte aussi "2026-10-27 14:00", today…)
    journalctl -kLes messages du noyau (comme sudo dmesg)
    journalctl -n 20Les 20 dernières lignes
    user@ubuntu:~$ journalctl -u cron -n 3
oct. 27 09:12:04 ubuntu systemd[1]: Started cron.service - Regular background program processing daemon.
oct. 27 10:17:01 ubuntu CRON[2804]: pam_unix(cron:session): session opened for user root(uid=0) by root(uid=0)
oct. 27 10:17:01 ubuntu CRON[2805]: (root) CMD (cd / && run-parts --report /etc/cron.hourly)

    Chaque ligne donne la date, la machine, le programme avec son PID entre crochets, puis le message. Les commandes de less fonctionnent : / pour chercher, G pour aller à la fin. Un utilisateur ordinaire du groupe adm (c'est ton cas sur Ubuntu) voit tous les journaux ; sinon, ajoute sudo.

    La méthode de dépannage

    Un service ne démarre pas ? 1) systemctl status nom pour voir l'état et les dernières lignes ; 2) journalctl -u nom -b pour l'historique complet ; 3) lis la première erreur, pas la dernière : c'est souvent elle la cause. Faute de frappe dans un fichier de configuration, port déjà utilisé, fichier introuvable… la réponse est presque toujours écrite.

    Écrire sa propre unité

    Chaque service est décrit par un fichier texte, une unité. Celles des paquets sont dans /usr/lib/systemd/system/ ; les tiennes vont dans /etc/systemd/system/. Exemple : transformer un petit script en service, qui démarre avec la machine et redémarre s'il plante.

    #!/bin/bash
while true; do
  echo "Bonjour, il est $(date +%T)"     # tout ce qu'un service affiche part dans le journal
  sleep 30
done
    [Unit]
Description=Service d'exemple qui dit bonjour
After=network.target                 # démarrer après le réseau

[Service]
ExecStart=/usr/local/bin/bonjour.sh      # chemin ABSOLU du programme
Restart=on-failure                     # le relancer s'il plante

[Install]
WantedBy=multi-user.target              # ce que fait « enable » : l'accrocher à cette cible
    user@ubuntu:~$ sudo chmod +x /usr/local/bin/bonjour.sh
user@ubuntu:~$ sudo systemctl daemon-reload              # systemd relit les unités (après CHAQUE modification)
user@ubuntu:~$ sudo systemctl enable --now bonjour
Created symlink /etc/systemd/system/multi-user.target.wants/bonjour.service → /etc/systemd/system/bonjour.service.
user@ubuntu:~$ journalctl -u bonjour -f
oct. 27 13:02:10 ubuntu systemd[1]: Started bonjour.service - Service d'exemple qui dit bonjour.
oct. 27 13:02:10 ubuntu bonjour.sh[638]: Bonjour, il est 13:02:10
oct. 27 13:02:40 ubuntu bonjour.sh[638]: Bonjour, il est 13:02:40

    Le message Created symlink montre ce que fait vraiment enable : un simple lien symbolique (module 02) qui rattache le service à sa cible. disable supprime ce lien. On reviendra aux unités au module 14, avec les timers, l'alternative moderne à cron.

    Glossaire du module

    UEFI / BIOS
    Firmware de la carte mère : première étape du démarrage.
    GRUB
    Chargeur d'amorçage : il charge le noyau et l'initramfs.
    Noyau
    Le cœur du système (vmlinuz), qui gère le matériel.
    initramfs
    Mini-système en mémoire qui aide le noyau à monter le vrai disque.
    systemd
    Le premier processus (PID 1), qui démarre et surveille tous les services.
    Service (démon)
    Programme qui tourne en arrière-plan, sans fenêtre.
    Unité
    Fichier qui décrit un service, une cible, un timer… pour systemd.
    Cible (target)
    Groupe d'unités à atteindre, comme graphical.target.
    systemctl
    Commande pour piloter systemd : status, start, enable…
    journalctl
    Commande pour lire le journal de systemd.

    🧠 Quiz : as-tu tout retenu ?

    1. Dans quel ordre se déroule le démarrage ?
    Le firmware lance GRUB, qui charge le noyau, qui lance systemd.
    2. Quel processus porte le PID 1 ?
    systemd est le premier processus lancé par le noyau, l'ancêtre de tous les autres.
    3. Après avoir modifié /etc/default/grub, que faut-il faire ?
    update-grub régénère /boot/grub/grub.cfg à partir de tes réglages.
    4. Tu veux qu'un service démarre maintenant ET à chaque démarrage. Quelle commande ?
    --now ajoute le démarrage immédiat à enable.
    5. Un service a été démarré avec start, sans enable. Après un redémarrage…
    start n'agit que sur le moment présent.
    6. Comment voir en direct les messages du service nginx ?
    -u filtre sur une unité, -f suit les nouveaux messages.
    7. Que faut-il lancer après avoir créé ou modifié un fichier .service ?
    systemd garde les unités en mémoire : daemon-reload les lui fait relire.
    8. Quelle cible démarre le système complet, mais sans interface graphique ?
    C'est la cible par défaut des serveurs.

    💬 Questions fréquentes

    Les questions qui reviennent le plus souvent sur ce module, avec leurs réponses.

    systemctl status bloque le terminal et je ne peux plus rien taper

    La sortie s'est ouverte dans le lecteur less : appuie sur q. Pour l'éviter : systemctl status cron --no-pager.

    Mon service affiche status=203/EXEC et refuse de démarrer

    systemd n'arrive pas à lancer le programme indiqué dans ExecStart. Vérifie que le chemin est absolu et exact, que le fichier est exécutable (chmod +x) et qu'un script commence bien par sa ligne #!/bin/bash.

    Quelle différence entre systemd et les anciens scripts /etc/init.d ?

    Avant systemd, les services étaient lancés un par un par des scripts (SysVinit). systemd les démarre en parallèle, suit leurs dépendances et les relance s'ils plantent. La commande service cron status existe encore par compatibilité : elle appelle systemctl.
